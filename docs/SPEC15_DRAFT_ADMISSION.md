# Executive summary

Draft profitability is an optional workload of the existing Spec 15 Controller, not a second controller. Rust proposer plugins now share its owner namespace, audit epochs, queue limit/expiry, Q1.31 rate classes and native-state commit discipline. Request-local suffix retrieval is the first supplied plugin. A custom MTP head can implement the same trait after separate training and qualification; no trained head is supplied or activated.

# Problem and design grounding

The linear verifier preserved the tested greedy trajectories but retrieval did not improve throughput. Accepted proposals alone are insufficient evidence for admission: block verification, recurrent/convolution replay and proposal generation consume time. The earlier four-probe figure of 1.0987 committed tokens per target call is verified progress, not Spec 15's declared-context residency coverage. Those counters remain distinct. Earlier block/sequential state comparisons passed the numerical gate and were not bitwise equal.

The design contract was written in SPEC15_IMPLEMENTATION.md before implementation. Its supplied SPEC15_SOURCE.md body stays unchanged. The existing verifier remains the only commit mechanism, including full unified KV/convolution/recurrent correction replay. Original model weights, tokenizer, FP32 explicit attention and fixed-point Metal operators are unchanged. The current module does not introduce approximate attention, early exit, paging, native MTP, or tensor batching.

# Files, interfaces and ownership

src/cache/drafts.rs extends the existing Controller State. DraftPolicy has no default and configure_drafts is one-time. Registration records exact model, tokenizer/template, quantization and private workload namespace identity. All identifiers carry the Controller owner; foreign handles fail. Native registrations use the artifact digest (including tokenizer/template bytes) for both model and tokenizer identity, conservatively preventing reuse after either changes. The numerical/KV profile is explicit. Namespaces must separate tenants and materially different workload classes.

prefix_key uses the existing Spec 15 radix path, including its partial tail. Binding a proposal computes H(identity, parent, proposed token IDs). Binding is single-use and outcome proposed counts must equal the bound length. This is a draft-history key; no GPU KV page is inserted into the opaque CPU prefix cache.

src/serving/native_automaton.rs supplies DraftProposer, ProposalContext, AutomatonProposer and its private AutomatonCursor. start tokenizes nowhere: callers provide boundary-tokenized IDs. no_draft measures and records baseline progress; next admits one plugin; next_best asks the Controller to arbitrate compatible plugins. Private cursors bind committed IDs, next logits and native unified state. Partial acceptance uses the existing verifier and publishes a new cursor only after replay completes.

The caller's cancelled future detaches a private Tokio job. Every target native command independently owns an Arc completion guard. Thus caller cancellation, proposer panic and Tokio abort cannot release admission while a queued/running native command still owns it. Registered native plugins must retain ProposalContext.completion through their own backend completion too. Plugins are trusted Rust code, not sandboxed extensions; a plugin that ignores this contract is unqualified. Caller-result channel handoff is an internal commit boundary, not proof that an end client received a token. Dropped result receivers contribute zero published committed tokens while retaining measured cost and completed verification counts.

# Admission, arbitration and audit

1. Validate bounded configuration and registration. At most 64 proposers and 1–3 active draft leases; each proposal reserves at most eight token IDs.
2. Cold qualification requires configured trust mass and reserves its configured observation allowance before work starts, including concurrent qualifications. Empty proposals consume an observation: excessively short allowances can bench retrieval before repeated content appears.
3. After qualification, earned admission requires mass above threshold and measured proposer nanoseconds per committed token strictly below the matching-identity no-draft baseline. Exact u128 cross-products avoid floating-point policy decisions. Acceptance alone cannot authorize earned admission.
4. Benched proposers can receive one configured epoch-spaced probe opportunity, with duplicate outstanding probes excluded. Selection orders cold qualification, probes, then earned work. Within a class it compares measured ns/token; registration ID resolves ties. Selection is advisory; request_draft rechecks admission under the same mutex.
5. Queued drafts are continuation-first, single-use and expire at max_wait_epochs. Cache-prefill and draft queued metadata share queue_depth; their active resources and within-class ordering remain distinct. The native adapter explicitly cancels a queued draft ticket and uses no-draft; retaining/polling tickets for actual serving belongs to the future scheduler.
6. audit refuses while a cache native-step lease or draft lease is active. It decays proposer mass once using the existing fixed-point rate/pressure arithmetic: recent acceptance uses the covered rate, no recent acceptance uses off-plan, critical pressure uses the strongest rate. Accepted fraction earns bounded configured mass; overflow is checked transactionally.

No-draft baselines are measured anew, shared only within an exact identity. The complete-observation cost window includes failed and unpublished attempts. A panic/abandoned lease increments lifetime unfinished, zeros mass, and clears the eligibility window because its cost is unknown. A later bounded probe may requalify using new complete observations; historical unfinished accounting remains visible forever. Ordinary failures zero mass and cannot reward acceptance. Target calls count commands admitted to the native worker, including failed native allocation/evaluation attempts; a failed bonus after successful verification retains both calls. Rejected host-side inputs or full Rust queues add no target command. These are not counts of completed full forward graphs. Lifetime ledgers never discard attempted-cost/progress counts. A counter overflow rejects the outcome before committing its increments and retires it as unfinished. Counter saturation on the unfinished path latches draft accounting faulted.

# Explicit experimental configuration

The Combined smoke configures max_proposers=4, work_limit=3, initial_mass=2147483647, admission_mass=268435455, reward_mass=536870911, qualification_trials=64 and probe_every_epochs=2. Cache rate classes, pressure multipliers, queue_depth=4 and max_wait_epochs=3 come from fixtures/cache-config-bench.json. These values are bench choices, not production defaults or recommendations. The smoke advances one audit epoch after each complete request; serving needs an explicit quiescent audit schedule. Production random-sampling draft values remain inactive and are a separate policy.

The native model executor still has a logical three-command bound. This is not proof that MLX emits at most three physical Metal command buffers. Proposal cost uses monotonic integer nanoseconds across proposal, verification and replay; full smoke elapsed time additionally includes host adapter work. Prefill, model load, networking and end-client latency are excluded. Baselines and variants use fixed baseline-first order on one host, without confidence intervals. Measured profitability is an engineering gate for this scope, not a statistical universal speedup guarantee.

# Observed Combined result

On Apple M5 Pro / 48 GiB, four authored 64-token requests produced 256/256 token IDs matching no-draft; maximum unified-state relative L2 was 1.0948060e-6 (gate 1e-5, not bitwise). Baseline decode was **20.1051 tok/s**, automaton **20.2057 tok/s**, a **+0.5004%** single-window difference. This small uncontrolled difference establishes no speedup. Load, prefill, network and client delivery are excluded; fixed order and no confidence interval prevent promotion on this result alone.

The plugin accepted **61/241 = 25.31%**, with **233 admitted target calls** for 256 committed tokens (**1.0987 tokens/call**). These are distinct from declared cache residency coverage. The proposer ledger recorded 191 complete observations, 252 internally published tokens and 229 target calls; four no-draft fallbacks supply the remaining four tokens/calls. Its measured-cost gate ended profitable=true for this short run, which is an empirical policy decision, not a statistically qualified gain. Before production, cost scoping, observation windows and a justified promotion margin need sustained alternating measurements.

Cancellation retained a completed target call and its cost with zero published tokens. The forced bonus-allocation failure retained **two admitted calls, zero committed tokens and one failure**, then recovered parent state and residency. A separate deliberately abandoned native receipt recorded one unfinished outcome; that visible gap is expected control evidence, not a silently dropped success.

# Next steps and lessons

Expose a worker-confined, version-bound hidden-state tap, then audit or train a checkpoint-bound Rust-native MTP/custom proposer behind this interface. The interface supplies neither trained weights nor hidden features today. Qualify the head against frozen target outputs and separately held-out requests. Reduce recurrent replay only with a derived factorization and the current verifier as oracle. Add the real streaming/continuous scheduler with per-lane ownership, quiescent audit epochs, cancellation and cost scopes; then measure TTFT, inter-token distributions, p95/p99, single/multi-lane aggregate throughput and complete agent workloads. Exact regular paging precedes compressed KV or predictive residency. No high-probability cache heuristic licenses skipped attention or missing layers on the exact path.

The integration was necessary to prevent acceptance counts from promoting a slower drafter and to bind admission lifetime to native work, rather than the receipt waiter. Shared policy allows the next proposer to be replaced or benched without replacing state-commit rules. Cold qualification length and workload scoping need measurement; passing a control-plane test does not establish model quality or a throughput win.
