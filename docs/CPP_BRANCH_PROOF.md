## FP32 multi-query attention kernel candidate

The submission-limit controls did not establish a useful gain. Next implement
an opt-in native attention mode 2: a Metal dot-product reduction and weighted-
value reduction around the existing precise FP32 softmax. It avoids materializing
query/key and probability/value product tensors. Preserve FP32 inputs/outputs,
causal masking, all target/MTP state and finite checks, and the unchanged scalar
snapshot reference. Mode 1 remains the existing SDPA experiment; mode 0 remains
default. Bound the candidate to the current 512-context architecture and 1..8
query rows. First require an independent FP64 attention oracle at NRMSE <=1e-5

Then require complete model logits/state and frozen-token gates before timing;
never widen tolerances to promote the kernel. Binary metadata must identify mode
2 explicitly. A kernel-only result cannot qualify DSpark/TurboQuant integration.
