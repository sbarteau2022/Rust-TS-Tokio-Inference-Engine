# Context

The requested destination is Desktop/RUST SERVER. The supplied complete source spec is preserved in SOURCE_SPEC.md. Section 3 steps 0–5 define this implementation. It is a compiler/kernel prototype beside the separate MLX serving architecture (spec 13), not yet an inference server. The user requires TypeScript 7.1 and npm-installed tsrs. No other project is modified.

# Decision

Trace builder in TypeScript records load/dot/add/relu/store, serializes generated FlatBuffers bindings; verified Rust reads feed typed SSA validation, then a strictly recognized GEMM+bias+ReLU fusion. Unknown graphs fail closed. SSA holds shapes, use counts, row-major layout and residency annotations. Multi-use tile operands stay in threadgroup storage; matrix accumulation stays in registers, followed by a threadgroup scratch tile for the fused scalar epilogue; no separate UMA intermediate is emitted. One SIMD group executes each 8x8 output tile; K-tail loads zero-pad. Shared Metal buffers hold f32 data; no CPU/GPU transfer buffers. CPU initialization and result inspection are explicit host accesses after GPU completion.

Tokio bounded submission returns a oneshot receipt before worker completion; blocking compilation/Metal wait runs off async workers. Worker errors and panics resolve to failure receipts. Resource budgets bound trace bytes, dimensions, operation count, queue depth and concurrent jobs. Jobs carry immutable trace bytes and named owned inputs; no external pointers or shader text accepted. os_signpost begin/end brackets every admitted job, including failures; optional Metal capture is an explicit CLI flag. Receipts distinguish compilation, GPU execution, validation and wall timings. GPU and end-to-end performance are reported separately.

# Judges and ordering

0: clean cargo build, generated Rust/TS bindings and npx tsrs plus TypeScript 7.1 check. 1: exact ordered normalized operation-list equality across languages before allocator implementation. 2: actual shared-buffer identity kernel byte comparison and misalignment rejection before fused execution. 3: 128-cubed and rectangular/tail GEMM against independent CPU f64 accumulation, then Python MLX. Tolerance abs 0.0002 + rel 0.0002; reject nonfinite inputs/results. 4: concurrent jobs, immutable input ownership, bounded queue rejection, malformed jobs, recovery, timing and signpost logging. 5: identical seeded f32 inputs on disk; MLX GPU materialization with explicit synchronization, warmup and repeated samples. Report cold compile separately and full dispatch overhead beside MLX call overhead. Bench numbers are shape-specific, not model-serving claims.

# Consequences

Small tiles emphasize correctness; no speed claim until measurement. Runtime compilation is a rare/cold cost. Bounds protect this prototype, not a security boundary for hostile remote clients. No HTTP, batching, KV, ANE, AMX, full MLIR, model loader or hyperbolic-cache integration in this milestone. Future server transport, repository management and scheduling need a separate design and judge.

# Alternatives considered

Full MLIR adds dependencies beyond the one-kernel proof. CPU fallback would obscure GPU failures and is rejected. Handwritten JSON wire would violate the FlatBuffers requirement. Unbounded tasks could exhaust unified memory and are rejected.

# Literature grounding

This implementation was not directly grounded in published literature. It applies established compiler, Rust ownership and bounded queue patterns.
