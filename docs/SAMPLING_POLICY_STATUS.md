# Decision and scope

Stewart supplied S1–S5 as DRAFT/PROPOSED, then explicitly ruled: **Keep proposed values inactive; make policy configuration explicit.** No proposed dynamic rate, threshold, or probation schedule is activated. The existing deterministic cadence is preserved as reproducible BENCH-MODE, never as approved random production sampling.

# Explicit configuration

`ValidationConfig { selection: Selection::DeterministicBench, every: 1000 }` is the compatibility configuration. `Runtime::with_sampling` takes it explicitly; existing constructors select this labeled compatibility posture. The test/bench cadence accepts 1..1000. `Selection::DynamicDraft` is refused with an inactive-draft error. Counters and receipts expose DETERMINISTIC-MODE; counters and benchmark output expose production_sampling_claims=false. Full per-execution synchronous checking remains cfg(test)/debug-validation, separate from background sampling. These labels supersede earlier use of "production sampling" for the fixed-cadence benchmark.

# Proposed values — documentation only

The draft names reduced 1/1000, normal 1/100, tightened 1/10, and 1000-receipt full probation. Its proposed transitions include 100 passed checks and 500 passed checks plus 50,000 receipts. These remain placeholders, not recommendations, and are not executable policy constants in the implementation.

# Corrections required before approving a random policy

Selection randomness must use an OS-seeded CSPRNG, hide seeds/draws from the request path, and define unbiased integer draws. Define lane identity, version fingerprints, reopen authorization, probation entry/reset, and the treatment of out-of-order checks from prior modes/versions. Probation cannot end just because 1000 receipts were delivered: its selected checks must resolve, with zero failures. Version changes need admission/lease fences so old checks cannot qualify new versions.

At independent selection probability p and a persistent fault present on every receipt, expected receipts to the first selected faulty receipt is 1/p. Expected preceding unselected receipts is (1-p)/p. The selected receipt itself is delivered unchecked; asynchronous checking can deliver additional receipts before detection. There is no finite worst-case detection bound for independent random selection when p<1. If only a fraction q of receipts manifests the fault, the simplified independent stationary expectation is 1/(p*q), not 1/p. Neither expression is a universal guarantee for intermittent/adversarial faults. Observed exposure since the last passed check is distinct from expected exposure and must be labeled separately.

The no-drop rule also needs a precise admission-pause scope (one lane versus all lanes), a limit on accepted-but-unchecked work, and shutdown accounting for unfinished checks. Per-lane mode/p, selected/passed/failed, version IDs, and queue residues are required for production claims. No such policy is claimed by this bench configuration.

# Verification, rollout, and next steps

Tests verify explicit deterministic configuration, one-per-thousand compatibility, all-receipt bench checking, labels on runtime/CLI receipts and counters, and refusal of DynamicDraft. Earlier mismatch, draining, bounded queue, and native resource-lifetime tests remain active. No production policy rollout or independent approval. Approve the corrected random-policy contract before implementing its CSPRNG and rate automaton; then pressure-test version/mode transitions and claim accounting independently of cache policy.
