# Question investigated

Do adversarial inputs and the local toolchain behave as assumed?

# Methodology and findings

Initial adversarial test expected every truncation of a FlatBuffer to fail. At byte 334, the removed bytes were unreferenced trailing alignment padding; the verifier correctly accepted the unchanged graph. This was an overstrict test assumption, not unsafe deserialization. Corrected judge: reject truncations that remove referenced bytes; any accepted padding-only truncation must decode identically. Original failing evidence is retained in evidence/adversarial-initial.log.

The metal-rs dependency brings block 0.1.6, which Cargo marks as future-incompatible. Current compiler succeeds. This is a dependency maintenance risk, not a clean future-toolchain claim.

# Recommendation

Keep structural verification and exact decoded-graph checks. Do not reject valid padding changes solely to satisfy a mistaken test. Revisit metal-rs dependencies before a production server release.

# Literature review

No research-paper claims. Local generated FlatBuffers verifier and observed test outputs are the evidence.

## Persistent-resource allocation finding (2026-10-21)

The first strict budget implementation assumed `heapBufferSizeAndAlign` upper-bounded a directly allocated shared MTLBuffer. Live adversarial tail shapes disproved that assumption: `MTLBuffer.allocatedSize` sometimes exceeded the heap reservation size. The implementation failed closed with `Metal allocation exceeded reserved size`; it did not admit the oversized allocation to the reusable pool. Original failed evidence is retained in `evidence/allocation-reservation-initial.log`. Work paused here to record the foundation finding before selecting a corrected allocation strategy. Heap layout requirements must not be treated as a direct-buffer allocation-size guarantee.


### Correction and judge

The backend now reserves at least whole host pages in addition to the Metal layout query, verifies the direct buffer's reported allocatedSize before admission, and counts actual admitted allocated bytes for idle/resident pool limits. If actual size exceeds the reservation, it still fails closed. New page-granularity and tight dynamic-shape tests pass. This is an admitted-buffer budget, not a hard limit on opaque driver/process memory. Compile/dispatch autorelease scopes prevent native temporary objects from accumulating across jobs.
